# 语文教学 RAG 助手 —— 详细设计说明

> 面向中学语文老师的生产级 RAG 系统。核心目标：把老师散落的 PDF / TXT / DOCX / DOC 教学资料**沉淀成可持续增值的私有知识库**，驱动「写教案、出题、答疑、错题沉淀」四个场景形成闭环。

---

## 1. 总体架构

```
                         ┌────────────────────────────────────────────┐
                         │                前端（Streamlit）            │
                         │  上传/扫描 · 四场景对话 · 溯源引用展示         │
                         └───────────────────┬────────────────────────┘
                                             │
拖文件进 ingest/private 或 ingest/public ────►│
                                             ▼
   ┌──────────────────────────────────────────────────────────────────┐
   │                       入库流水线（pipeline）                       │
   │  解析(PDF/TXT/DOCX/DOC) → 分类打标签 → 智能切片 → 向量化 → 入库      │
   └───────────────┬───────────────────────────────┬──────────────────┘
                   ▼                               ▼
          ┌─────────────────┐             ┌──────────────────┐
          │  ChromaDB 双库   │             │  SQLite 状态库     │
          │ public_base      │             │  文件hash/状态/标签 │
          │ private_kb       │             └──────────────────┘
          └────────┬────────┘
                   ▼
          ┌─────────────────┐
          │  检索层（retrieval）│  向量 + BM25 多路召回，RRF 融合
          └────────┬────────┘   私有优先 + 权威加权
                   ▼
          ┌─────────────────┐
          │  四大场景链（chains）│  写教案 / 出题 / 答疑 / 学情分析
          └─────────────────┘
```

### 数据流闭环

```
上课/批改 → 新资料拖入 ingest/ → 自动入库 → 下次备课/出题自动召回 → 再产生新资料 → …
```

这条闭环不需要额外定时任务：入库即生效，检索无缓存，每次查询都实时命中最新数据。

## 2. 模块详解

### 2.1 配置层 `src/config.py`

- 加载 `.env`（API key）与 `config.yaml`（标签枚举、切片规则、模型与检索参数）。
- 集中暴露路径常量与 `api_key_ready()`（判断 key 是否已填真实值）。
- 所有可调参数集中在 `config.yaml`，改配置不改代码。

### 2.2 摄入层 `src/ingestion/`

| 文件 | 职责 |
|---|---|
| `loader.py` | 按扩展名分发解析：TXT（utf-8→gb18030→utf-16 自动探测）、PDF（pypdf）、DOCX（python-docx，含表格）、DOC（Word/WPS COM 转换） |
| `state.py` | SQLite 状态库：文件 hash 去重、处理状态、标签、chunk 数、错误信息 |
| `watcher.py` | watchdog 监听两个文件夹，新文件自动入库；提供 `scan_existing` 手动兜底 |

**幂等设计**：文件内容 hash 相同且已 `processed` → 跳过；hash 变化 → 先删旧 chunk 再重入，保证向量库与磁盘一致。

### 2.3 打标签层 `src/tagging/`

入库**之前**分类（切片策略依赖文档类型）。六维标签：

- **学段**（枚举：七年级上…高三下）
- **单元**（自由文本）
- **篇目**（自由文本，如「桃花源记」）
- **知识点**（枚举：文言实词/虚词、特殊句式、现代文赏析、作文立意…）
- **文档类型**（枚举：教案/课堂笔记/学生错题/习题/学生作答样本/文言笔记/作文材料/其他）
- **学情标签**（枚举：班级共性错误/易混淆点/学生易踩坑 + 自由文本学情描述）

实现：DeepSeek `deepseek-chat` JSON 模式 + few-shot；文件名/子目录名作为线索（如放在 `初三/桃花源记/` 下预填学段篇目）；结果做枚举校验后落到每个 chunk 的 metadata。

### 2.4 智能切片层 `src/chunking/`（核心差异化）

不搞一刀切均分，按文档类型分流到四种切片器：

| 文档类型 | 最小切片单元 | 边界识别依据 | 保留的结构字段 |
|---|---|---|---|
| 教案/课堂笔记 | 单个教学环节 | 第X课时、一/二/三、（一）、【导入】【重难点】【课堂提问】【拓展】 | 环节 |
| 学生错题/作答样本/习题 | 单道题 | 题号 `1.` `1、` `（1）` `第1题` | 题号、题干、学生答案、教师批注 |
| 文言笔记 | 单个实词/虚词/特殊句式 | 【之】、`1. 之`、`之：`、判断句/被动句… | 词条 |
| 作文材料 | 单条主题 + 单个学生立意 | 【主题】、`主题：`、偏题/平庸/深刻 | 主题、立意 |

- 找不到结构标记时回退到 `RecursiveCharacterTextSplitter` 语义切片（句界优先，1200 字块 + 120 字重叠）。
- 错题切片特别保留「学生错在哪 + 教师批注」三段，这是私有库最核心的资产，也是出题干扰项、教案重难点的直接来源。

### 2.5 向量库 `src/vectorstore/`

- ChromaDB 持久化，**两个独立 collection**：`public_base`、`private_kb`。
- 元数据全部扁平化为 str/int/float/bool（列表 JSON 序列化）。
- chunk id = `{文件hash}-{序号}`，支持按 `source_hash` 整文件删除（重新入库用）。
- 权限与优先级天然隔离：私有库与公共库永不混排。

### 2.6 检索层 `src/retrieval/`

**三条核心规则在此落地：**

1. **私有优先、公共补充** —— `retrieve()` 分别召回私有 `top_k` 与公共 `top_k`，私有结果永远排在前面；出题/学情分析只查私有库。
2. **冲突以教师手写批注为准** —— 每个 chunk 带 `authority` 字段（教师批注=5 > 教材/教师教案=4 > 教参/优质课=3 > 学生作答=2 > 其他=1），排序时叠加 `weight × authority_boost`；同时各场景的 prompt 里显式写明「私有资料冲突时以教师手写批注版本为准」。
3. **全量溯源** —— 每个 `RetrievedDoc` 带 `source_file + library`，生成时以 `[n]` 编号引用，前端区分【私有知识库】/【公共基准库】。

**多路召回：**
- 向量召回：bge-base-zh-v1.5 dense（768 维，余弦），支持元数据过滤（按篇目/学段/类型/库限定范围）。
- 关键词召回：jieba 分词 + BM25，文言实词/虚词这类精确词匹配场景比纯向量更准。
- 两者 RRF 融合（`rrf_k=60`），再叠加 authority 加权。

### 2.7 场景链 `src/chains/`

| 链 | 检索 | 模型 | 输出 | 关键规则 |
|---|---|---|---|---|
| 写教案 | 私有优先+公共补充 | `deepseek-reasoner` | Markdown 教案 | 复用旧框架、提取往届学生痛点进重难点、优先用验证过的问题 |
| 出题 | 仅私有库 | `deepseek-chat` JSON | 试题+答案+评分细则+命题说明 | 薄弱点必须来自私有文档、干扰项取真实错误作答、对标课标不超纲 |
| 答疑 | 私有优先+公共补充 | `deepseek-chat` | 启发式回复 | 不直接给完整答案 |
| 学情分析 | 仅私有库 | `deepseek-chat` JSON | 高频错误/易混淆/共性错误/建议 | 结论必须来自私有文档 |

### 2.8 前端 `app/streamlit_app.py`

- 侧边栏：API key 状态、双库统计、上传（私有/公共二选一）、扫描、重建索引。
- 主区五个 Tab：写教案 / 出题 / 答疑 / 学情分析 / 文件管理。
- 溯源引用以折叠面板展示，每条标 `[n]` + 🟢私有/🔵公共 + 文件名 + 文档类型。

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| Embedding | 本地 bge-base-zh-v1.5 | DeepSeek 无 embedding 接口；BGE 中文效果好、可离线、CPU 即可跑（裸 transformers） |
| 向量库 | ChromaDB | 单机零运维、持久化、元数据过滤成熟 |
| 关键词召回 | jieba + BM25 | 文言实词/虚词精确匹配，弥补纯向量短板 |
| 双 collection | 物理隔离 | 私有/公共权限与优先级天然分离，检索时可独立加权 |
| 权威加权 + prompt 双保险 | 批注优先 | 排序层面 + 生成层面同时保证「教师批注优先」 |
| 切片前置分类 | 先分类再切片 | 切片策略由文档类型决定，分类错误则切片策略错位 |

## 4. 运行与部署

### 4.1 本地运行

见 [README.md](../README.md)「快速开始」。

### 4.2 首次运行注意

- 首次入库会下载 BGE 模型（`bge-base-zh-v1.5`，约 400MB）到本地缓存，首次调用预热约 60s。
- `.doc` 老格式依赖本机 Word/WPS 的 COM 接口。
- 扫描版 PDF（无文本层）会被跳过并提示，需先 OCR。

### 4.3 环境变量

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek API key（`deepseek-chat` 与 `deepseek-reasoner` 共用） |

## 5. 扩展指南

- **新增文档类型切片策略**：在 `src/chunking/` 新增一个 chunker，并在 `__init__.py` 的 `_CHUNKERS` 注册。
- **调整标签枚举**：改 `config.yaml` 的 `tagging` 段即可，分类 prompt 会自动引用。
- **新增场景**：在 `src/chains/` 加一个模块，仿照现有链的 `run()`，前端加一个 Tab。
- **换 embedding 模型**：改 `config.yaml` 的 `embedding.model_name`。
- **写教案换推理模型**：`lesson_plan.py` 里 `get_reason_llm()` 换成 `get_chat_llm()` 即可。
- **切换云端向量库**（如 Milvus/Qdrant）：实现 `src/vectorstore/store.py` 的同一组接口即可，上层无感。

---

## 6. 已知限制与后续优化

1. **扫描版 PDF 需 OCR**：当前只抽取文本层，图片型 PDF 返回空。
2. **无跨语言/多模态**：纯中文文本检索，不含图片、板书照片的 OCR/理解。
3. **rerank 未启用**：可加 `BAAI/bge-reranker` 进一步提升精度（需额外下载约 1GB 模型）。
4. **单一用户单机**：ChromaDB 本地持久化，未做多用户鉴权与并发写入队列。
5. **切片边界依赖结构标记**：结构不规范的手写材料可能退化为语义切片，可针对高频格式补充正则。
6. **`.doc` 依赖本机 Office/WPS**：无 Office 环境建议先把 `.doc` 另存为 `.docx` 或 `.txt`。
